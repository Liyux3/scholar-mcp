各客户端启动 Scholar 的方式相同。最快的办法是使用 `scholar-mcp` 命令，它会找出电脑上已安装的客户端并写好配置。

```bash
uv tool install --python 3.12 \
  --find-links https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html \
  "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9"
scholar-mcp install --all --dry-run   # 预览所有检测到的客户端
scholar-mcp install --all             # 或者逐个指定：claude-code codex cursor
```

写入前会先备份，中途出错也不会留下损坏的文件，重复运行结果相同。你手写的 `scholar` 条目不会被改动，除非加 `--force`。全部选项和各客户端的配置文件位置见[命令行](/scholar-mcp/zh-cn/cli/#install-和-uninstall)。

## 手动配置

下方源码命令固定到已验收的 0.9 开发版。插件市场、桌面包和容器当前安装稳定版 0.8.5；使用本文的 CLI 和科学数据能力时，采用源码安装。

以下配置均通过 `uvx` 启动，无需提前安装。首次启动时，uvx 会准备好 Python 3.12 和本地排序模型。`--find-links` 为 Intel 版 macOS 和 ARM 版 Windows 提供现成的安装包，其他平台照常从 PyPI 安装。每段配置都用 `SCHOLAR_MCP_EXTENSIONS=research` 启用了研究工具集，删去这一行即只保留六个核心工具。

<TabItem label="Claude Code">

在终端中添加，`--scope user` 让它对所有项目生效。

```bash
claude mcp add scholar --scope user -e SCHOLAR_MCP_EXTENSIONS=research \
  -- uvx --python 3.12 \
  --find-links https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html \
  --from 'scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9' scholar-mcp
```

也可装插件，效果一样，还会带上研究工具集和 Deep Research 技能。

```bash
claude plugin marketplace add Liyux3/scholar-mcp
claude plugin install scholar-mcp@scholar-mcp
```

<TabItem label="Claude Desktop">

macOS 上最省事的是用安装包。在[最新版本](https://github.com/Liyux3/scholar-mcp/releases/latest)里下载 `scholar-mcp-darwin-arm64-<version>.mcpb`（Apple 芯片）或 `scholar-mcp-darwin-x86_64-<version>.mcpb`（Intel），用 Claude Desktop 打开即可。安装包自带 Python、本地排序模型和研究工具，安装时会问你要不要填密钥。

任何平台都可以手动编辑 `claude_desktop_config.json`（Settings → Developer → Edit Config）。

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "scholar": {
      "command": "uvx",
      "args": [
        "--python", "3.12",
        "--find-links", "https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html",
        "--from", "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9", "scholar-mcp"
      ],
      "env": { "SCHOLAR_MCP_EXTENSIONS": "research" }
    }
  }
}
```

保存后重启 Claude Desktop。

<TabItem label="Codex">

在 `~/.codex/config.toml` 里加一段。

```toml title="~/.codex/config.toml"
[mcp_servers.scholar]
command = "uvx"
args = [
  "--python", "3.12",
  "--find-links", "https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html",
  "--from", "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9", "scholar-mcp",
]
startup_timeout_sec = 60
tool_timeout_sec = 600

[mcp_servers.scholar.env]
SCHOLAR_MCP_EXTENSIONS = "research"
```

超时要设得长一些，因为首次启动需要准备环境，一次完整的搜索也要等待多个数据源和引用扩展。若只想对单个项目生效，写在项目中的 `.codex/config.toml` 即可。

```bash

```

## 更多智能体

`scholar-mcp install` 还能为以下智能体写好配置，并带上各自需要的超时和字段：

| 智能体 | 命令 |
|---|---|
| Qwen Code | `scholar-mcp install qwen-code` |
| Kimi Code | `scholar-mcp install kimi-code` |
| Qoder CLI | `scholar-mcp install qoder-cli` |
| CodeBuddy Code | `scholar-mcp install codebuddy` |
| iFlow CLI (legacy) | `scholar-mcp install iflow` |
| MiniMax Code | `scholar-mcp install minimax` |
| DeepSeek Harness | `scholar-mcp install deepseek` |
| TRAE CLI 2.0 | `scholar-mcp install trae-cli` |
| MiMo Code | `scholar-mcp install mimocode` |
| ZCode | `scholar-mcp install zcode` |
| Cline CLI、Kilo Code、Amp | `scholar-mcp install cline`、`kilo`、`amp` |
| GitHub Copilot CLI、Factory Droid、Junie CLI、Augment CLI | `scholar-mcp install copilot-cli`、`factory`、`junie`、`augment` |
| Warp、LM Studio | `scholar-mcp install warp`、`lmstudio` |

Trae、通义灵码、百度 Comate、Cherry Studio、ChatWise，以及 Cline 和 Roo Code 的编辑器插件（Cline 命令行版可用 `install` 写好），把 MCP 列表保存在各自的设置界面里。把上方**其他**标签中的 JSON 粘贴到它们的 MCP 设置中即可。

### DeepSeek Harness

安装器将官方 `@deepseek-ai/dsh-mcp-client` 插件写入 `~/.dsh/cordis.patch.yml`，也支持 `DSH_HOME` 指定的数据目录。这份用户级 Cordis 补丁对各个 profile 生效，已有的 YAML、注释和 `!!js` 表达式保持原样；Scholar 的受管区块可以用同一安装器更新或卸载。

插件调用其他客户端共用的 Scholar 命令，工具超时为 600 秒，工具名称形如 `mcp__scholar__search_papers`。只给某个自定义 profile 使用时，可将同样的 insert 放进该 profile 的 `cordis.patch.yml`；项目目录中的补丁需要通过 `dsh <profile> --patch <file>` 显式加载。详见 [DeepSeek 官方 MCP 说明](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/mcp/mcp-client)。

### ZCode 与自定义配置目录

`scholar-mcp install zcode` 将 stdio 配置写入 `~/.zcode/cli/config.json` 的 `mcp.servers`。用户显式设置的 `features.mcp=false` 会保留，并提示用户检查这项选择。模型凭据由 ZCode 自行管理。

安装器遵循各智能体自己的目录设置，包括 `QWEN_HOME`、`KIMI_CODE_HOME`、`CODEBUDDY_CONFIG_DIR`、`QODER_CONFIG_DIR`、`MINIMAX_DATA_DIR`（也支持 `MAVIS_DATA_DIR`）和 `TRAE_HOME`。安装 Scholar 和启动智能体时，使用相同的目录设置即可。Kimi Code 2.4 与 MiniMax Code 0.7 会直接加载各自的 MCP 配置文件。

## 智能体框架

框架可以通过原生 MCP 客户端启动同一条 Scholar 命令。[LangChain 与 LangGraph](https://github.com/langchain-ai/langchain-mcp-adapters) 使用 `MultiServerMCPClient`，[AgentScope](https://github.com/agentscope-ai/agentscope/tree/main/src/agentscope/mcp) 使用 `MCPClient` 与 `StdioMCPConfig`。加载 Scholar 的工具后，将它们交给智能体现有的工具注册表即可。

一次研究会连续调用多个工具时，保持连接，结束后按框架的会话生命周期关闭。Scholar 在独立进程中运行，框架和 Scholar 可以各自管理 Python 依赖。托管框架则使用前面说明的可达 HTTP 部署。

## 其他安装方式

| 渠道 | 入口 |
|---|---|
| PyPI + uv tool | `uv tool install scholar-mcp`，再用 `scholar-mcp install` 注册客户端 |
| PyPI + uvx | 在任意客户端配置里写 `uvx scholar-mcp` |
| 官方 MCP Registry | `io.github.Liyux3/scholar-mcp` |
| 容器 | `ghcr.io/liyux3/scholar-mcp:<version>` |
| Claude Desktop | [GitHub Releases](https://github.com/Liyux3/scholar-mcp/releases) 里的 MCPB 安装包 |
| Codex、Claude Code、Cursor | 仓库里的插件和插件市场清单 |

仓库中还有启动脚本，macOS 和 Linux 用 `scripts/launch.sh`，Windows 用 `scripts/launch.cmd` 或 `scripts/launch.ps1`。已有 uv 时直接使用，否则把 uv 装进一个独立目录，不改动 shell 配置。
