Say in one sentence what you are looking for, and your agent gets a ranked list of papers. It can then open a paper to read the text and figures, follow citations backward and forward, and save the useful papers and notes for the next session.

Scholar works in Claude, Codex, Cursor, VS Code, Gemini CLI, OpenCode and any other MCP client. The same features are available from the [command line](/scholar-mcp/cli/) and [Python](/scholar-mcp/python/).

## How it differs

**Many sources, one ranking.** Sources read a question differently. Semantic search needs the whole sentence, while keyword search works best with few precise words, so each source gets the form it handles best and all results go into one candidate pool. Records of the same paper in DOI, arXiv, Semantic Scholar, OpenAlex, PubMed and OpenReview merge into one. Scholar then follows citations from the most relevant papers and ranks everything once more with one model. On LitSearch the top-five hit rate is 0.62, ten points above Exa's paper search ([benchmarks](/scholar-mcp/benchmarks/)).

**The full text, not only abstracts.** `read_paper` finds a downloadable PDF in archives, open repositories and preprint servers, reads pages 1 to 10 by default and lists every figure and table by name. Read again with that name and the agent sees the figure with the text around it.

**A library that lasts beyond the session.** Saved papers keep stable identifiers, notes, tags and PDF paths in a local SQLite store with full-text search. The same records can be exported to Obsidian, synced to Zotero or published to Notion, and notes you edit there are read back the next time the agent reads the library.
