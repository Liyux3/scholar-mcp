Every client starts Scholar the same way. The fastest route is the `scholar-mcp` command, which finds the clients on your computer and writes their configuration:

```bash
uv tool install --python 3.12 \
  --find-links https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html \
  "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9"
scholar-mcp install --all --dry-run   # preview every detected client
scholar-mcp install --all             # or name them: claude-code codex cursor
```

Files are backed up before a change, a failed write leaves nothing broken, and running it twice changes nothing. A `scholar` entry you wrote by hand stays untouched unless you pass `--force`. [Command line](/scholar-mcp/cli/#install-and-uninstall) lists every option and the file each client uses.

## Manual configuration

Source commands below use the tested 0.9 preview. Marketplace plugins, desktop bundles and containers currently install stable 0.8.5; use the source install for the CLI and science features described here.

The snippets below start the server through `uvx`, so nothing needs installing first. On first launch uvx prepares Python 3.12 and the local ranking model. The `--find-links` index has ready-made packages for Intel macOS and Windows on ARM, and other platforms install from PyPI as usual. Each snippet enables the research profile with `SCHOLAR_MCP_EXTENSIONS=research`. Remove that line to keep only the six core tools.

<TabItem label="Claude Code">

Add the server from your terminal. `--scope user` makes it available in every project:

```bash
claude mcp add scholar --scope user -e SCHOLAR_MCP_EXTENSIONS=research \
  -- uvx --python 3.12 \
  --find-links https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html \
  --from 'scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9' scholar-mcp
```

Or install the plugin, which adds the same server with the research profile and the Deep Research skill:

```bash
claude plugin marketplace add Liyux3/scholar-mcp
claude plugin install scholar-mcp@scholar-mcp
```

</TabItem>
<TabItem label="Claude Desktop">

On macOS the simplest route is the desktop bundle. Download `scholar-mcp-darwin-arm64-<version>.mcpb` (Apple silicon) or `scholar-mcp-darwin-x86_64-<version>.mcpb` (Intel) from the [latest release](https://github.com/Liyux3/scholar-mcp/releases/latest) and open it with Claude Desktop. It includes Python, the local ranking model and the research tools, and asks for optional keys while installing.

On any platform you can also edit `claude_desktop_config.json` (Settings, Developer, Edit Config):

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "scholar": {
      "command": "uvx",
      "args": [
        "--python", "3.12",
        "--find-links", "https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html",
        "--from", "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9", "scholar-mcp"
      ],
      "env": { "SCHOLAR_MCP_EXTENSIONS": "research" }
    }
  }
}
```

Restart Claude Desktop after saving.

<TabItem label="Codex">

Add a server table to `~/.codex/config.toml`:

```toml title="~/.codex/config.toml"
[mcp_servers.scholar]
command = "uvx"
args = [
  "--python", "3.12",
  "--find-links", "https://github.com/Liyux3/scholar-mcp/releases/latest/download/wheel-index.html",
  "--from", "scholar-mcp[rerank] @ git+https://github.com/Liyux3/scholar-mcp.git@6d2bdbd612da2d3c78bb1ec16f253288189083e9", "scholar-mcp",
]
startup_timeout_sec = 60
tool_timeout_sec = 600

[mcp_servers.scholar.env]
SCHOLAR_MCP_EXTENSIONS = "research"
```

The long timeouts leave room for the first launch, which prepares the environment, and for a full search that waits on many sources and citation expansion. For one project only, use `.codex/config.toml` in that project.

Or install the plugin with the research profile and the Deep Research skill:

```bash
codex plugin marketplace add Liyux3/scholar-mcp
codex plugin add scholar-mcp@scholar-mcp
```

The multi-architecture container speaks stdio by default:

```bash
docker run -i --rm -e SCHOLAR_MCP_EXTENSIONS=research \
  ghcr.io/liyux3/scholar-mcp:latest
```

When a client cannot start a program itself, such as an agent in a web page, Scholar can run as a network service. Run `scholar-mcp serve --http`, or set `SCHOLAR_MCP_TRANSPORT=http`. The Streamable HTTP endpoint defaults to `http://127.0.0.1:8000/mcp`. Cloud agents cannot reach localhost on your computer, so they need a reachable, protected deployment.

### DeepSeek Harness

The installer adds the official `@deepseek-ai/dsh-mcp-client` plugin through a Cordis YAML insert in `~/.dsh/cordis.patch.yml`, or the directory selected by `DSH_HOME`. This home patch applies across profiles. Existing YAML, comments and `!!js` expressions stay intact; the managed Scholar entry can be updated or removed through the same installer.

The plugin calls the same Scholar command as other clients, with a 600-second tool timeout. DeepSeek exposes names such as `mcp__scholar__search_papers`. For a custom profile, its own `cordis.patch.yml` accepts the same insert; a project-local overlay is loaded explicitly with `dsh <profile> --patch <file>`. See the [official MCP client reference](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/mcp/mcp-client).

### ZCode and custom configuration directories

`scholar-mcp install zcode` writes the stdio entry under `mcp.servers` in `~/.zcode/cli/config.json`. It preserves an explicit `features.mcp=false` and reports that setting for you to review. ZCode manages its model credentials separately.

The installer follows each agent's configuration directory: `QWEN_HOME`, `KIMI_CODE_HOME`, `CODEBUDDY_CONFIG_DIR`, `QODER_CONFIG_DIR`, `MINIMAX_DATA_DIR` (or `MAVIS_DATA_DIR`) and `TRAE_HOME`. Pass the same directory setting when installing Scholar and starting the agent. Kimi Code 2.4 and MiniMax Code 0.7 load their MCP files directly.

## Agent frameworks

Your framework can start the same Scholar command through its native MCP client. [LangChain and LangGraph](https://github.com/langchain-ai/langchain-mcp-adapters) use `MultiServerMCPClient`; [AgentScope](https://github.com/agentscope-ai/agentscope/tree/main/src/agentscope/mcp) uses `MCPClient` with `StdioMCPConfig`. Load Scholar's tools once and pass them to your agent's existing tool registry.

Keep a connection open while the agent makes several calls, then close it with the framework's session lifecycle. Scholar runs in its own process, so your framework and Scholar can use their own Python dependencies. Hosted frameworks use the reachable HTTP deployment described above.

## Other channels

| Channel | Entry |
|---|---|
| PyPI with uv tool | `uv tool install scholar-mcp`, then `scholar-mcp install` registers detected clients |
| PyPI with uvx | `uvx scholar-mcp` in any client configuration |
| Official MCP Registry | `io.github.Liyux3/scholar-mcp` |
| Container | `ghcr.io/liyux3/scholar-mcp:<version>` |
| Claude Desktop | MCPB bundles attached to [GitHub Releases](https://github.com/Liyux3/scholar-mcp/releases) |
| Codex, Claude Code, Cursor | Repository plugin and marketplace manifests |

The repository also includes portable launchers, `scripts/launch.sh` for macOS and Linux and `scripts/launch.cmd` or `scripts/launch.ps1` for Windows. They reuse uv when it is present and otherwise bootstrap it into an application directory without editing shell profiles.
